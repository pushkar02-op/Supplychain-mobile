# Audit Phase 4C: Order Creation Workflow (Frontend)

## 1. Executive Summary
This audit analyzes the Flutter order creation workflow to identify mismatches between the "Phase 2 Mart-scoped identity" rules and the actual implementation. 

**Key Findings:**
- **Contract Mismatch**: The API payload sends `mart_id` (Internal) but is missing `mart_name` (Required by Rules).
- **Backend Constraints**: The current backend implementation *requires* `mart_id` and ignores `mart_name`.
- **State Bug**: The `_selectedMart` state variable in `OrderEntryScreen` is not properly updated, breaking the loading indicator logic.
- **Inconsistency**: Service methods mix Identity scopes (`fetch` uses Name, `create` uses ID).

## 2. Files Involved
- **UI**: `mobile/lib/screens/order_entry_screen.dart`
- **Service**: `mobile/lib/services/order_service.dart`
- **Backend Model (Reference)**: `backend/app/db/schemas/order.py`

## 3. State Propagation & Mart Identity
### UI Selection (Trace)
1.  `OrderEntryScreen` initializes and calls `_loadMarts()`.
2.  `OrderService.fetchMartList()` calls GET `/orders/mart-names`, returning `List<Map<String, dynamic>>` (contains `{id, name}`).
3.  User selects Mart from `DropdownButtonFormField`.
4.  **State**: `_selectedMartId` (int) is updated.
5.  `onChanged` callback computes `martName` locally from the list to call `_loadItemsForMart(martName)`.
6.  **Critical Bug**: The class member `String? _selectedMart` is **never updated** in `onChanged`. It remains `null`.
    - Impact: The loading indicator `if (_selectedMart != null && _items.isEmpty)` never activates.

### State Variables
| Variable | Type | Purpose | Status |
| :--- | :--- | :--- | :--- |
| `_selectedMartId` | `int?` | Stores selected Mart ID for API payload | **Active** (Used) |
| `_selectedMart` | `String?` | intended to store Mart Name due to Phase 2 rules | **Broken** (Unused/Null) |
| `_items` | `List` | Stores items filtered by Mart Name | **Active** |

## 4. API Payload Analysis
### Constructed Payload (Frontend)
Located in `_submit()`:
```dart
{
  'item_id': 123,           // from _selectedItem['item_id']
  'mart_id': 456,           // from _selectedMartId
  'order_date': '2025-01-01',
  'quantity_ordered': 10.0,
  'unit': 'kg'
}
```

### Backend Contract (Reality vs Rules)
| Field | Backend `OrderCreate` (Reality) | Phase 2 Rules | Mismatch? |
| :--- | :--- | :--- | :--- |
| `mart_id` | **Required** (int) | **Internal Only** | 🔴 **YES** (Frontend must send it to work, but rules say it shouldn't be exposed at boundary) |
| `mart_name` | Optional (str) | **Required** | 🔴 **YES** (Missing from contents) |

## 5. Missing / Incorrect Fields
- **Missing**: `mart_name`. The Rules state "mart_name is required at API boundary". Frontend fails to send this.
- **Incorrect Usage**: `mart_id` is being sent. While required by the backend, it violates the "Internal Only" rule. Given "NO backend changes", the Frontend *must* continue sending `mart_id`, but should *also* send `mart_name` to satisfy the "Required" rule (even if redundant).

## 6. Recommended Frontend-Only Fixes

### Fix 1: Enforce Mart Name in Payload
Update `OrderService.createOrder` to accept `martName` and include it in the POST body. This ensures compliance with "mart_name is required at API boundary".

**Before**:
```dart
static Future<dynamic> createOrder({ ..., required int martId }) async {
  // ... data: { 'mart_id': martId, ... }
}
```

**After**:
```dart
static Future<dynamic> createOrder({ 
  ..., 
  required int martId, 
  required String martName 
}) async {
  // ... data: { 'mart_id': martId, 'mart_name': martName, ... }
}
```

### Fix 2: Fix `_selectedMart` State Bug
Update `OrderEntryScreen` to properly store the mart name in `_selectedMart` when a selection is made.

**Change in `onChanged`**:
```dart
onChanged: (val) {
  setState(() {
    _selectedMartId = val;
    if (val != null) {
      _selectedMart = _marts.firstWhere((m) => m['id'] == val)['name']; // Capture name in state
    }
  });
  if (_selectedMart != null) {
    _loadItemsForMart(_selectedMart!);
  }
}
```

### Fix 3: Standardize Service Signatures
Ensure all Mart-related service methods accept `martName` where applicable to align with Phase 2 identity rules.

## 7. Risk Assessment
- **Field Addition (`mart_name`)**: **Low Risk**. Backend Pydantic model (`OrderBase`) has `mart_name: Optional[str]`, so it will accept the field without error. The backend logic `create_order` explicitly ignores/pops it, so no side effects will occur.
- **State Fix**: **Low Risk**. Fixing `_selectedMart` only affects the visibility of the loading indicator (UI polish).

## 8. Conclusion
The frontend is currently functional against the backend but non-compliant with the "Mart-scoped identity" design rules. By adding `mart_name` to the payload and fixing the local state bug, we can satisfy the audit requirements and improve UI responsiveness without violating backend invariants.
