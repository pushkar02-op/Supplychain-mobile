**Date:** 2025-12-31  
**Auditor:** Antigravity

## A. Current Schema (`app/db/models/order.py`)

| Column | Type | Nullable | Classification |
|--------|------|----------|----------------|
| `id` | Integer (PK) | N | Canonical |
| `item_id` | Integer (FK) | N | Canonical |
| `mart_id` | Integer (FK) | N | Canonical |
| `order_date` | Date | N | Canonical |
| `quantity_ordered` | **Float** ⚠️ | N | Canonical |
| `quantity_dispatched` | **Float** ⚠️ | N (default 0) | **DERIVED** |
| `status` | String | N (default "Pending") | **DERIVED** |
| `unit` | String | N | Canonical |

### Constraints
- ✅ Unique: `(item_id, order_date, mart_id)`
- ⚠️ No DB-level check for `quantity_dispatched <= quantity_ordered`
- ❌ No DB constraint preventing negative quantities

### Risks
1. **Float Precision**: Quantities use Float instead of Numeric/Decimal
2. **Derived Fields Exposed**: `quantity_dispatched` and `status` are mutable via ORM

## B. Service Logic (`app/services/order.py`)

### B1. `create_order` (Lines 43-104)
- ✅ Enforces uniqueness (item_id, order_date, mart_id)
- ✅ Resolves mart_name to mart_id
- ⚠️ No validation on quantity (can be negative/zero)
- ⚠️ No unit validation against item's default UOM

### B2. `update_order` (Lines 147-192)
- ❌ **CRITICAL**: Allows changing `quantity_ordered` freely
- ❌ **BUG**: Status calculation uses `original_dispatched` but still sets status incorrectly
  ```python
  if ord_.quantity_ordered <= original_dispatched:
      ord_.status = "Completed"
  else:
      ord_.status = "Partially Completed"
  ```
  - Never sets "Pending" if dispatched == 0
- ⚠️ Allows changing `mart_id` silently

### B3. `delete_order` (Lines 195-214)
- ❌ No check for existing dispatches
- ❌ Allows deleting orders with `quantity_dispatched > 0`
- Risk: Orphaned dispatch records / data corruption

## C. Order ↔ Dispatch Coupling (`app/services/dispatch_entry.py:320-338`)

```python
order.quantity_dispatched = (order.quantity_dispatched or 0) + dispatched_quantity
order.status = (
    "Completed"
    if order.quantity_dispatched >= order.quantity_ordered
    else "Partially Completed"
)
```

### Observations
- ✅ Status recalculated on dispatch (correct flow)
- ⚠️ No over-dispatch prevention at order level
- ⚠️ `quantity_dispatched` is incremented but never verified against order constraints
