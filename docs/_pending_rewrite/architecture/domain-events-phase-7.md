# Domain Events & External Truth (Phase 7)

## Purpose
The **Domain Events** layer allows external systems (analytics, notifications, audit) to observe the state of the Supply Chain system **without coupling** to internal database schemas or mutable logic.

## Core Principles
1.  **Fact-Based**: Events represent immutable facts that have already occurred (e.g., `InventoryTxnCommitted`).
2.  **Outbox Pattern**: Events are persisted to a `domain_events` table within the **same atomic transaction** as the state change. This guarantees consistency (no "dual write" issues).
3.  **Strictly Append-Only**: Events are never modified or deleted.
4.  **No Logic**: Events contain only data references (IDs) and snapshots of the change. They do not contain business logic.

## Event Model
Stored in `domain_events` table (Postgres).

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | Integer | Unique Sequence ID. |
| `event_type` | String | Dot-notation type (e.g., `inventory_txn.committed`). |
| `aggregate_type` | String | The entity usage (e.g., `inventory_txn`). |
| `aggregate_id` | String | The primary key of the aggregate. |
| `payload` | JSONB | Structured data specific to the event. |
| `occurred_at` | DateTime | Timestamp of the actual business occurrence. |

## Supported Events

### 1. `inventory_txn.committed`
Emitted when stock moves (IN, OUT, ADJUST).
- **Trigger**: `InventoryTxnCreate` service.
- **Payload**:
  ```json
  {
    "txn_id": 123,
    "item_id": 45,
    "batch_id": 67,
    "qty": 100.0,
    "unit": "kg",
    "txn_type": "IN"
  }
  ```

### 2. `reconciliation.resolved`
Emitted when ledger drift is resolved by an admin.
- **Trigger**: `resolve_drift` service.
- **Payload**:
  ```json
  {
    "record_id": 10,
    "batch_id": 67,
    "drift_resolved": -5.0,
    "adjustment_txn_id": 124
  }
  ```

### 3. `dispatch.completed`
Emitted when a dispatch entry is created/updated.
- **Trigger**: `create_dispatch_entry` service.
- **Payload**:
  ```json
  {
    "dispatch_id": 89,
    "order_id": 55,
    "item_id": 45,
    "qty": 20.0
  }
  ```

### 4. `order.fulfilled`
Emitted when an order transitions to "Completed" status.
- **Trigger**: `_update_order_after_dispatch`.
- **Payload**:
  ```json
  {
    "order_id": 55,
    "item_id": 45,
    "mart_id": 3,
    "total_qty": 100.0
  }
  ```

## Future Work (Phase 8+)
- **Event Relay**: A background worker (e.g., Kafka Connect, Debezium, or custom poller) will read `domain_events` and publish them to a message bus.
- **Retention**: Periodic archiving of old events.
