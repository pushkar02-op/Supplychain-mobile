# Orders Screen Architecture — Phase F6

## Purpose

The Orders screen displays orders scheduled for a **single operational date**. It does not show backlogs or cross-day summaries.

## Date Semantics

- Orders are **strictly date-scoped**
- Default date: Today (`DateTime.now()`)
- Header displays: "Today — Wednesday, Jan 15" or "Wednesday, Jan 15"
- Subheader: "Orders scheduled for this date"
- No backlog indicators exist
- Incomplete orders remain on their original date
- Date change requires explicit user action (calendar icon tap)

> “Order creation and adjustment semantics are defined in `orders-entry-model.md`.”

## Order Card Content

Each order card displays:

| Field | Description |
|-------|-------------|
| Item name | Primary identifier |
| Mart name | Secondary identifier |
| Ordered | Quantity ordered with unit |
| Dispatched | Quantity already dispatched |
| **Remaining** | Explicit calculation (Ordered - Dispatched) |
| Status | See status rules below |

## Status Rules

| Status Text | Condition | Color |
|-------------|-----------|-------|
| Fully dispatched | dispatched >= ordered | Green |
| Partially dispatched | dispatched > 0 | Amber |
| Not dispatched yet | dispatched == 0 | Red |

## Action Placement

### Primary Actions
- **FAB (Floating Action Button)**: "Add Order" — bottom-right
- **Card tap**: Navigate to Dispatch Entry

### Secondary Actions (PopupMenu)
- Dispatch
- Edit
- Delete (with confirmation dialog)

## Navigation

| Action | Destination |
|--------|-------------|
| Add Order (FAB) | `/order-entry` |
| Card tap | `/dispatch-entry` (with order data) |
| Edit | `/order-entry` (with existing order) |

## Filters

- **Date**: Tap calendar icon to change
- **Mart**: Dropdown with "All Marts" default

## Empty State

- Icon: `Icons.assignment_outlined`
- Text: "No orders for this date"
- Hint: "Tap + to create an order"
