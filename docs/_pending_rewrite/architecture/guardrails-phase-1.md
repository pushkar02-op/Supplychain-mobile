# Architecture Phase 1: Guardrails

**Status**: Active / Enforced
**Source**: `backend/tests/test_architecture.py`

## Overview
This phase explicitly enforces architectural boundaries to prevent degradation during future development. It freezes the current state of technical debt and strictly forbids new violations.

## Enforced Rules

### 1. No Direct DB Access in API Layer
**Rule**: API endpoints (in `app/api`) must delegate business logic and data access to Services (`app/services`).
**Forbidden**:
- `db.query(...)`
- `db.add(...)`
- `db.commit()`
- `db.delete(...)`
**Enforcement**: `test_api_layer_should_not_access_db_directly`
**Waivers**: Existing files (e.g., `audit_log.py`, `batch.py`, `report.py`, etc.) are explicitly allowed but marked as debt. New files must comply.

### 2. No SQLAlchemy Core Imports
**Rule**: API and Service layers should not import low-level SQLAlchemy Core components (`text`, `select`, `func`, `case`, `desc`) to prevent raw SQL leakage and ensure ORM consistency.
**Allowed**: `sqlalchemy.orm.Session` (for logic dependency injection).
**Enforcement**: `test_api_routes_do_not_import_sqlalchemy_core`
**Waivers**: `reports.py`, `uom.py` (legacy query construction).

### 3. Explicit Admin Authentication
**Rule**: All endpoints in `app/api/admin_*.py` and `app/api/endpoints/admin_*.py` must explicitly declare dependency on `get_current_active_admin`.
**Forbidden**: Implicit `current_user.is_admin` checks inside function bodies.
**Enforcement**: `test_admin_routes_must_be_secured`
**Status**: Fully enforced. No waivers.

### 4. Append-Only Models
**Rule**: `InventoryTxn`, `DispatchEntry`, and `DispatchReversal` are ledger records and must never be deleted directly.
**Enforcement**: `test_append_only_models_safety`
**Mechanism**: Checks for `db.delete()` or `query(...).delete()` usage on these models.

## Non-Goals
- Refactoring existing "Direct DB Access" violations is NOT a goal of Phase 1. Isolate and freeze only.
- Moving `reports.py` logic to a proper query builder is future work.

## Operational Note
If `test_architecture.py` fails, do NOT disable the test.
- If fixing a bug in legacy code requires a violation, add the file to the `WAIVERS` list in `test_architecture.py`.
- If writing NEW code, adhere to the rules.
