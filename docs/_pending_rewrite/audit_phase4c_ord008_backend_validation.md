# Audit Phase 4C: Backend Order Creation Validation

## 1. Executive Summary
Empirical testing confirms the backend **blindly trusts** `mart_id` and **ignores** `mart_name`, while paradoxically **requiring** `mart_name` to be present in the payload (schema validation).

**Status**: 🔴 **NOT Phase-2 Safe**
The backend forces the frontend to resolve identity and holds `mart_id` as the source of truth, violating the "Mart-scoped identity" rule where the backend should resolve the Name.

## 2. Test Results

| Test Case | Payload Diff | Result | Analysis |
| :--- | :--- | :--- | :--- |
| **Test 1** | `mart_id` only | 🔴 **422 Unprocessable** | Failed Pydantic validation. `mart_name` key is missing from payload, which is required by schema (despite being Optional type). |
| **Test 2** | `mart_id` + `mart_name` | ⚪ Inferred Success | Standard happy path. |
| **Test 3** | `mart_id=9999` + `mart_name=...` | 🔴 **500 Internal Error** | Backend attempted to insert `mart_id=9999` directly into DB, causing Foreign Key Violation. **Proves `mart_id` is the authority and `mart_name` is ignored.** |
| **Test 4** | `mart_name` only | 🔴 **422 Unprocessable** | Failed Pydantic validation. `mart_id` is required. |

## 3. Evidence
- **Test 3 Behavior**: The 500 Error (IntegrityError) confirms that no lookup/resolution occurred. The logic simply used `9999`.
- **Code Confirmation**: `services/order.py` explicitly performs `order_data.pop("mart_name", None)` before creating the model.
- **Test 1 Behavior**: The 422 Error confirms that `mart_name` is treated as a required *field* in the JSON (even if value is null).

## 4. Conclusion
1.  **Backend Logic**: Uses `mart_id` exclusively.
2.  **Schema Constraint**: Requires BOTH `mart_id` (for logic) and `mart_name` (for schema satisfaction).
3.  **Conflict Handling**: No conflict check exists. `mart_id` overwrites everything.
4.  **Implicit Resolution**: Does NOT exist.

## 5. Recommendation (Next Steps)
To achieve Phase 2 compliance:
1.  **Frontend**: MUST send both `mart_id` (current valid) and `mart_name` (decoration).
2.  **Backend Fix (Type B)**:
    -   Update `create_order` to Lookup Mart by `mart_name` if `mart_id` is missing? (Future)
    -   OR Validate `mart_id` matches `mart_name`?
    -   Currently, the system is "Frontend-Authored Identity".

**Immediate Action**: Frontend must send `mart_name` (even if dummy) to pass 422, but MUST send correct `mart_id` to avoid 500.
